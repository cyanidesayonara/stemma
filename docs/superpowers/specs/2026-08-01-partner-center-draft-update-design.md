# Partner Center draft update (issue #134, slice 2)

Date: 2026-08-01  
Status: Approved for implementation (credentials configure smoke passed)  
Issue: [#134](https://github.com/cyanidesayonara/stemma/issues/134)

## Goal

Push a Partner Center **draft** from GitHub Actions using:

- Package URL from an existing GitHub Release tag (`stemma.msix`)
- Listing fields from `store/listing.yaml` (description, features, what's new, …)

Default stops at draft. Publish is a separate explicit mode.

## Modes (`partner-center-submit.yml`)

| Mode | Behavior |
|---|---|
| `configure` | Credentials only (already verified) |
| `update_draft` | Build payloads from YAML + tag; `update` with `product-update` + `metadata-update`; **no publish** |
| `publish_draft` | `publish` only (submit current Partner Center draft for certification) |

## Payloads

Generated by `scripts/build_partner_center_payloads.py`:

- `product-update.json` — packages array (`packageUrl`, `en-us`, `X64`)
- `metadata-update.json` — listing module for `en-us` from YAML

Release version is the tag with leading `v` stripped; must exist in `whats_new`.

## Non-goals

- Auto-run on every `v*` tag (optional later)
- Screenshot upload via API
- Full get-merge PUT safety net (add if live metadata update fails)

## Live gate

After merge: run `update_draft` with `tag=v2.6.0`, then inspect Partner Center draft before any `publish_draft`.
